# MMR Pipeline Worklog - 2026-04-30

## Summary

This document records the current DB/API-ready MMR pipeline refactor work.

The project moved from notebook/CSV-driven execution toward a testable pipeline:

```text
DB raw tables -> MMR calculation pipeline -> DB result tables
```

The same boundary is prepared for the later backend API flow:

```text
Backend API -> MMR calculation pipeline -> Backend API result save
```

### 4. Main Pipeline Entrypoint

Added one command-line pipeline runner.

File:
- `scripts/main_pipeline.py`

Command:

```bash
python scripts/main_pipeline.py --source db --sink db
```

Pipeline stages:
1. Load raw match rows.
2. Clean match data.
3. Add basic derived features.
4. Derive position weights.
5. Compute raw and normalized game impact.
6. Compute n-person contribution.
7. Compute opponent comparison score.
8. Update ELO-based MMR.
9. Save row-level and summary results.

### 5. Database Migrations

Added SQL migrations.

Files:
- `migrations/001_create_mmr_result_tables.sql`
- `migrations/002_drop_player_game_id_from_mmr_match_results.sql`

Created output tables:

```text
mmr_match_results
mmr_user_summary
```

Rationale:
- `mmr_match_results`: row-level match/player MMR history and calculation basis.
- `mmr_user_summary`: current user-level and position-level summary for fast API/profile/ranking reads.

`player_game_id` was removed from `mmr_match_results` because it is not needed in the output contract. `replay_code + puuid + position` is sufficient for result interpretation.

## Current Caveat

Result saving currently uses append mode.

If this command is run repeatedly:

```bash
python scripts/main_pipeline.py --source db --sink db
```

the same calculated result set will be appended again.

Recommended next improvement:
- Add a `run_id` column, or
- Add idempotent upsert/delete-then-insert behavior by `calculated_at` batch or source dataset version.
